# OIDC Setup Guide for PyPI Publishing

This guide explains how to set up OpenID Connect (OIDC) trusted publishing for your GRAFT package.

## What is OIDC Trusted Publishing?

OIDC (OpenID Connect) trusted publishing is a modern, secure authentication method that eliminates the need for API tokens. Instead of storing secrets, PyPI trusts your GitHub repository based on its identity.

## Benefits over API Tokens

- ✅ **No secrets to manage** - No API tokens to store or rotate
- ✅ **More secure** - Uses short-lived tokens generated by GitHub
- ✅ **Automatic** - No manual token management
- ✅ **Fine-grained** - Can be restricted to specific workflows/branches

## Setup Instructions

### 1. Configure PyPI Trusted Publisher (Production)

1. Go to https://pypi.org/manage/account/publishing/
2. Click "Add a new pending publisher"
3. Fill in the form:
   - **PyPI Project Name**: `graft-pytorch`
   - **Owner**: `ashishjv1` (your GitHub username)
   - **Repository name**: `GRAFT`
   - **Workflow filename**: `publish.yml`
   - **Environment name**: `pypi`
4. Click "Add"

### 2. Configure TestPyPI Trusted Publisher (Testing)

1. Go to https://test.pypi.org/manage/account/publishing/
2. Click "Add a new pending publisher"
3. Fill in the form:
   - **PyPI Project Name**: `graft-pytorch`
   - **Owner**: `ashishjv1`
   - **Repository name**: `GRAFT`
   - **Workflow filename**: `test.yml`
   - **Environment name**: `testpypi`
4. Click "Add"

### 3. Configure GitHub Environments

#### For Production PyPI:
1. Go to your GitHub repo → Settings → Environments
2. Create environment named `pypi`
3. Add protection rules (recommended):
   - ✅ Required reviewers (add yourself)
   - ✅ Restrict to protected branches (main/master)
   - ✅ Wait timer: 5 minutes (optional)

#### For TestPyPI:
1. Create environment named `testpypi`
2. Protection rules (optional for testing):
   - ✅ Restrict to protected branches (test)

## How It Works

### TestPyPI Publishing (test.yml)
- **Trigger**: Push to `test` branch
- **Process**: Test → Build → Publish to TestPyPI
- **OIDC**: Uses `testpypi` environment

### Production PyPI Publishing (publish.yml)
- **Trigger**: Create a GitHub release
- **Process**: Build → Publish to PyPI
- **OIDC**: Uses `pypi` environment with protection rules

## Workflow Structure

### Test Workflow (`test.yml`)
```yaml
permissions:
  id-token: write  # OIDC requirement

jobs:
  publish-testpypi:
    environment:
      name: testpypi
      url: https://test.pypi.org/p/graft-pytorch
    permissions:
      id-token: write
```

### Production Workflow (`publish.yml`)
```yaml
permissions:
  id-token: write  # OIDC requirement

jobs:
  publish-pypi:
    environment:
      name: pypi
      url: https://pypi.org/p/graft-pytorch
    permissions:
      id-token: write
```

## Publishing Process

### To TestPyPI:
1. Push changes to `test` branch
2. GitHub Actions runs tests
3. If tests pass, automatically publishes to TestPyPI
4. Test installation: `pip install --index-url https://test.pypi.org/simple/ graft-pytorch`

### To Production PyPI:
1. Create a GitHub release from `main` branch
2. GitHub Actions builds and publishes to PyPI
3. Users can install: `pip install graft-pytorch`

## Security Notes

- ✅ No API tokens stored in GitHub secrets
- ✅ OIDC tokens are short-lived (15 minutes)
- ✅ Restricted to specific repositories/workflows
- ✅ Environment protection rules add extra security
- ✅ Full audit trail in both GitHub and PyPI

## Troubleshooting

### Common Issues:

1. **"Repository not found" error**
   - Verify the repository name is exactly `GRAFT` in PyPI settings
   - Check the GitHub owner is `ashishjv1`

2. **"Environment not found" error**
   - Ensure environments `pypi` and `testpypi` are created in GitHub
   - Verify environment names match exactly in workflows

3. **"Workflow not found" error**
   - Ensure workflow filenames match exactly (`publish.yml`, `test.yml`)
   - Check workflows are in `.github/workflows/` directory

4. **"Permission denied" error**
   - Verify `id-token: write` permission is set
   - Check environment protection rules aren't blocking the workflow

### Verification Steps:

1. Check PyPI project exists: https://pypi.org/project/graft-pytorch/
2. Check TestPyPI project exists: https://test.pypi.org/project/graft-pytorch/
3. Verify GitHub environments exist in repo settings
4. Test with a push to `test` branch first

## Migration from API Tokens

If you previously used API tokens:

1. Set up OIDC as described above
2. Test with TestPyPI first
3. Once working, remove old API token secrets:
   - `PYPI_API_TOKEN`
   - `TESTPYPI_API_TOKEN`
4. Delete the tokens from PyPI account settings
